Oh **absolutely** — and ML may actually be one of the cleanest places to apply this architecture.

The translation is not:

> “Turn JSON Schema into a neural network.”

It is:

> **Treat an ML model as one possible provider for a governed capability, while keeping the meaning, admissible data, expected outcome, evaluation, and human experience outside the model.**

That gives you something much stronger than a normal ML pipeline.

## The SDA → ML translation

At scenario altitude:

```text
GIVEN              WHEN                 THEN
Input              Event                Outcome
Data               Action               Experience
```

At ML altitude:

```text
FEATURE / CONTEXT
       ↓
MODEL INFERENCE
       ↓
PREDICTION / GENERATION
       ↓
ADMISSION / INTERPRETATION
       ↓
EXPERIENCE
```

The critical point is that **the model output is not automatically the Scenario Outcome**.

It is testimony.

```text
Scenario Input
      ↓
ML Responsibility
      ↓
Model Provider
      ↓
Model Output
      ↓
deterministic evaluation
      ↓
admitted semantic result
      ↓
Scenario Outcome
      ↓
Experience
```

That is almost perfectly aligned with the rest of SideFX.

## Example: classify a mortgage document

Traditional ML architecture might look like:

```text
document
   ↓
classification model
   ↓
"pay stub"
```

SideFX would model it more rigorously:

```text
SCENARIO

Input
─────
Admitted mortgage document

Event
─────
Resolve document classification

Outcome
───────
The document's usable mortgage-document
classification is established
```

Now descend into the event:

```text
Resolve Document Classification
        ↓
prepare model input
        ↓
invoke classification provider
        ↓
Model Testimony

{
  label: "pay_stub",
  confidence: 0.93,
  model: "...",
  ...
}

        ↓
evaluate admitted labels
evaluate confidence
evaluate evidence requirements
evaluate policy
        ↓
Classification Admission

        ↓
DocumentClassification
```

So:

```text
MODEL SAYS
"pay_stub"

≠

ENTERPRISE KNOWS
"this is an admitted pay stub"
```

That distinction is **huge**.

## The killer principle

I think the ML version of your architecture can be reduced to one line:

> **Models provide intelligence; capabilities own meaning.**

That keeps model training, inference, replacement, evaluation, explainability, cost, drift, and provider choice underneath a stable semantic boundary.

And because the Scenario contract gives you **Input → Event → Outcome**, you already have a natural unit for ML training and evaluation that is much richer than “prompt in, string out.”

That could become one of SideFX's strongest applications.
